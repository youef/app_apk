# المزامنة الذكية للعز TV

يتابع AutoSync الأفلام والمسلسلات والحلقات في Supabase بمعرّفات UUID. يبدأ مع خدمة Python، ويُبقي مهام الفحص والمصادر وسجل النتائج على القرص الدائم، ويعيد محاولة المهام التي انقطعت. إغلاق صفحة الإدارة لا يوقف العامل.

لوحة المزامنة: [استوديو العز TV](https://app-apk-oquy.onrender.com/#smart-sync). يوجد رابط إليها في لوحة إدارة العز الحالية. تتطلب كلمة مرور الاستوديو، وتعرض اتصال العامل، النتائج، المصادر المفقودة، آخر فحص، الموعد القادم، والتغييرات التي تنتظر الرفع.

## تشغيل المزامنة على الكمبيوتر

شغّل \`python launch.py\` (أو ملف التشغيل على Windows) وافتح
[المزامنة الذكية المحلية](http://127.0.0.1:8765/#smart-sync). سجّل دخول مسؤول
Supabase من زر تسجيل الدخول داخل الاستوديو. يستخدم العامل جلسة المسؤول محليًا
من دون مفتاح خادم سري، ويحفظ الطابور على الكمبيوتر. لا تُحفظ كلمة المرور على القرص؛
سجّل الدخول مجددًا عند إعادة تشغيل البرنامج. تسجيل الخروج يوقف استخدام الجلسة
بعد انتهاء المهمة الجارية. يعمل هذا الخيار على اتصال محلي فقط، ولا يغيّر إعداد Render.

## تجهيز الخدمة الموجودة على Render

تحتوي النسخة على ملفي Docker متوافقين مع بناء المستودع من الجذر أو من `python-cloud-studio`. يجب أن تكون الخدمة مرتبطة بفرع `main` في `youef/app_apk`، وأن تُشغّل نسخة واحدة وعامل Uvicorn واحدًا. يحافظ التحديث على تسجيل دخول الاستوديو وواجهته الحالية.

طبّق ملف `python-cloud-studio/autosync_schema.sql` على مشروع Supabase نفسه قبل تشغيل النسخة الجديدة. يضيف صفحات المصادر للمسلسلات والحلقات وجدول `aseel_media_sources` لحفظ تاريخ المصادر. التغيير إضافي ولا ينقل المحتوى أو يغير حالة النشر والحقوق. تاريخ المصادر متاح للمسؤولين والعامل فقط؛ يستمر المشغّل العام باستخدام `stream_url` و`stream_variants`.

اضبط هذه المتغيرات من **Environment** في Render:

| المتغير | القيمة أو الغرض |
| --- | --- |
| `ALEZZ_PUBLIC_MODE` | `1` لتفعيل حماية الاستوديو |
| `ALEZZ_SITE_PASSWORD` | كلمة مرور الموقع الحالية، 12 حرفًا فأكثر |
| `ALEZZ_SITE_SECRET` | سر الجلسات الحالي، 32 حرفًا فأكثر |
| `ALEZZ_DATA_DIR` | `/var/data` على القرص الدائم |
| `ALEZZ_SUPABASE_URL` | عنوان مشروع Supabase الحالي |
| `ALEZZ_SUPABASE_SERVICE_ROLE_KEY` | مفتاح `service_role` السري؛ داخل Render فقط |
| `ALEZZ_SUPABASE_SECRET_KEY` | بديل للمفتاح السابق عند استخدام مفتاح `sb_secret_` الحديث؛ يكفي أحدهما |
| `ALEZZ_AUTOSYNC_ENABLED` | `1` لبدء العامل تلقائيًا |
| `ALEZZ_AUTOSYNC_MODE` | `auto` أو `http` أو `headless` |
| `ALEZZ_AUTOSYNC_SOURCE_INTERVAL_HOURS` | `4` (إعادة اكتشاف المصادر كل 4 ساعات، وأبكر إذا اقترب انتهاء رابط موقّع) |
| `ALEZZ_AUTOSYNC_INTERVAL_HOURS` | متغير قديم؛ تجاهله العامل الجديد حتى لا تُجبره إعدادات Render السابقة على 30 دقيقة |
| `ALEZZ_AUTOSYNC_CHECK_MINUTES` | `5` (فحص صحة الروابط كل 5 دقائق تقريبًا) |
| `ALEZZ_AUTOSYNC_CONCURRENCY` | `3`–`5` عمّال متوازيين بحسب إعداد Render |
| `ALEZZ_AUTOSYNC_PUBLISH_APPROVED` | `1` نشر المسودات المعتمدة مسبقًا فقط عند وجود مصدر محفوظ ورابط فيديو مباشر تم التحقق منه؛ لا يعتمد الحقوق آليًا |
| `ALEZZ_SITE_NAMES` | اختياري: أسماء المواقع التي تُزال من العناوين، مفصولة بفاصلة |

استخدم القرص الحالي إن كان موجودًا، وتأكد من أن مسار ربطه `/var/data`. تحفظ Render الملفات على القرص الدائم عبر إعادة النشر والتشغيل؛ ملفات الخدمة العادية مؤقتة. التشغيل المستمر والقرص يتطلبان خطة مناسبة، ولا تكفي خدمة تنام عند الخمول لتحقيق تشغيل على مدار الساعة. راجع [توثيق القرص الدائم في Render](https://render.com/docs/disks).

لا تضع أي مفتاح سري في GitHub أو صفحات الإدارة أو `config.js`. لا تتطلب الواجهة قراءة مفتاح العامل؛ جميع اتصالاته مع Supabase تتم من الخادم.

## الأوضاع والفحص

- `http`: يستخرج الروابط من HTML وJSON ووسوم الفيديو وصفحات المشغلات العامة، دون تشغيل متصفح.
- `auto`: يبدأ بالطلبات المباشرة، ويستخدم Chromium المخفي عند تعذر الحصول على رابط صالح بالطريقة العادية.
- `headless`: يشغّل المتصفح المخفي ضمن عملية الاكتشاف. يأتي Chromium مع صورة Docker، ولا تظهر نافذة على جهاز المستخدم.

يفحص العامل الروابط دوريًا كل خمس دقائق تقريبًا، ويعيد اكتشاف المصادر كل 4 ساعات عندما يوجد مصدر أصلي. يتدرج إعادة الفحص الفاشل بين دقيقة وخمس دقائق لتقليل الحمل، ويعيد ترتيب الأعمال القديمة المخزنة على القرص عند تطبيق السياسة الجديدة. يقدّم الروابط القريبة من انتهاء الصلاحية عندما يتضمن الرابط وقت انتهاء واضحًا، ويستخدم سجل نجاح المصدر وإخفاقه لترتيب المرشحين. لا يخمّن وقت انتهاء توقيع غير معروف.

يتحقق الفحص من ترويسة MP4/WebM أو قائمة HLS ومقطع منها، ويرفض صفحات HTML الفارغة أو صفحات الخطأ. هذا فحص لاستجابة الوسائط؛ توافق الترميز وCORS والجهاز قد يحتاج تجربة تشغيل على جهاز العرض. لا يغيّر `stream_url` إلا بعد التحقق من بديل صالح، ويحتفظ بالرابط السابق وسبب الإخفاق عند غياب البدائل. تُنشر حتى ثمانية بدائل متوافقة مع حد `stream_variants`، ويظل باقي تاريخ المصادر محفوظًا.

صفحة المشغل تُعرض بصفتها صفحة مشغل، ولا تُعامل استجابتها HTTP 200 وحدها على أنها فيديو صالح. لا يجري تجاوز DRM أو تسجيل الدخول أو حواجز الحماية. إذا منع موقع الوصول، تظهر النتيجة في السجل وتُستكمل بقية المكتبة.

## الاستخدام اليومي

من **المزامنة الذكية** يمكنك:

1. تحديث المكتبة من Supabase، أو تقديم موعد فحصها أو تجديد مصادرها.
2. البحث عن فيلم أو حلقة، وتحديد مجموعة للفحص أو فحص عنصر واحد.
3. فتح **المصادر** لمراجعة صفحات المصدر والمشغلات والجودات، وثقة كل مصدر، وتاريخ اكتشافه وفحصه.
4. إضافة صفحة أصلية لعنصر مفقود المصدر مرة واحدة. تستخدم المهام التالية الصفحة المحفوظة تلقائيًا.
5. إيقاف العامل مؤقتًا واستئنافه. تبقى حالة الإيقاف والمصادر والمهام محفوظة عبر إعادة التشغيل.

يعتمد الربط على الجدول وUUID. تشابه العناوين لا يكفي لدمج عملين. تُحفظ الأعمال الجديدة غير المعتمدة كمسودات، ولا تغيّر صيانة الروابط حقول الحقوق أو المرجع القانوني للعمل.

**قواعد المسودة التلقائية:** يتحول الفيلم أو الحلقة المنشوران إلى `draft` فور غياب صفحة المصدر الأصلية المحفوظة؛ أو بعد ثلاث دورات فشل متتالية دون رابط وسائط مباشر صالح أو مشغل أساسي يمكن إثبات إتاحة صفحته. وتتحول المسلسلات بلا مصدر أصلي إلى مسودة، وكذلك المسلسلات التي لا يُعثر فيها على أي حلقات بعد ثلاث دورات اكتشاف. يُحفظ سجل جميع المصادر ولا تُحذف الأعمال. إذا كانت المسودة **معتمدة الحقوق مسبقًا**، وبها مصدر أصلي محفوظ واجتاز مشغّل مباشر فحص الوسائط، يستطيع العامل نشرها تلقائيًا إذا لم تكن مخفية وكانت سلسلتها الأصلية منشورة ومعتمدة. تبقى الأعمال غير المعتمدة مسودات، ولا يعتمد العامل حقوقًا جديدة مطلقًا.

**ملاحظة التضمين:** إتاحة صفحة Embed 1vid تعني أن الصفحة قابلة للوصول فقط، لا أن الفيديو يعمل؛ لذلك تظل نتيجة صفحة التضمين `suspect` وليست `healthy` دون فحص فيديو مباشر.

FetchV إضافة تعمل في متصفح المستخدم؛ لا تُثبت كإضافة على Render ولا يتحكم العامل بجلستها. يمكن الاستمرار في لصق الروابط المنسوخة منها في الاستوديو. يستخدم العامل مراقبة طلبات الفيديو العادية في Chromium عندما يحتاجها، وفق [توثيق مراقبة الشبكة في Playwright](https://playwright.dev/python/docs/network)، دون الاعتماد على واجهة غير موثقة للإضافة.

## التحقق من النشر والاستعادة

قبل النشر، ثبّت `requirements-dev.txt` وشغّل اختبارات Python من داخل `python-cloud-studio`، وفحص JavaScript للواجهة. تنفذ GitHub Actions الاختبارات نفسها عند تعديل الاستوديو.

بعد اكتمال نشر Render، افحص [حالة الخدمة](https://app-apk-oquy.onrender.com/healthz). نجاح `ok` يثبت استجابة الويب فقط. يلزم أن تعرض معلومات AutoSync عاملًا متصلًا ونبضة حديثة، وأن تصبح `autosync_ready` صحيحة بعد نجاح جلب المكتبة دون خطأ إعداد. راجع أيضًا لوحة المزامنة وسجلها للتأكد من أن عنصرًا حقيقيًا فُحص وأن نتيجته حُفظت؛ لا يُعد بدء النشر أو الاستجابة 200 دليلًا كافيًا.

لاختبار الاستعادة، سجّل عدد المصادر وموعد مهمة، ثم أعد تشغيل الخدمة من Render. يجب أن تبقى المصادر والسجل، وأن يستكمل العامل المهمة المحفوظة. قفل العملية يمنع عاملًا ثانيًا على القرص نفسه، وتحجز كل مهمة أثناء معالجتها. لا تنقل ملفات الحالة أو تحذف القرص عند تحديث الكود.

عند توقف الاتصال بـ Supabase تبقى تغييرات الرفع في الطابور مع إعادة المحاولة. عند فقد المصدر الأصلي يظهر التنبيه بوضوح؛ لا يصنع العامل رابطًا بديلًا من اسم الفيلم أو رابط تشغيل منتهي.
