# مركز العز لفحص أمان المواقع

مسار الدخول: `https://app-apk-oquy.onrender.com/studio/security` — المسؤولون المسجلون في Supabase فقط.

## التغطية الفعلية

- فحص قراءة محدود لنطاق HTTPS **عام مسجل بواسطة مسؤول**. يتم رفض IP وlocalhost والشبكات الداخلية والروابط ذات بيانات الدخول والمنافذ الخاصة.
- لا تتبع للروابط المحوّلة. يعاد التحقق من DNS لجميع الاتصالات ويمنع الوصول إلى عناوين خاصة/داخلية (SSRF).
- ثقة شهادة TLS، حالة HTTP، HSTS وCSP وX-Frame-Options وX-Content-Type-Options وReferrer-Policy وPermissions-Policy وسمات الكوكيز في الاستجابة.
- اختبار سياسة CORS بعملية GET آمنة وبحجم صغير.
- التعرّف المبدئي على WordPress وبعض منصات المنتديات. الإصدارات والإضافات تحتاج تحققاً منفصلاً.
- فحص بصمات أربعة مسارات ملفات شائعة قد تكشف تهيئة حساسة؛ يقرأ بضع كيلوبايت ولا يحفظ محتويات الملفات أو الأسرار.
- قراءة حالة `robots.txt` و`security.txt`.
- استكشاف **مسارات الإدارة وتسجيل الدخول وواجهات API العامة** من عناصر HTML وملفات JavaScript العامة؛ مع **ستة طلبات GET محدودة** لبعض مسارات الدخول الشائعة، وحد أقصى أربعة مسارات ظاهرة مسبقًا في الموقع، ولا تُرسل نماذج أو كلمات مرور.
- التقاط **بيانات Network في Chromium/Playwright عبر Chrome DevTools Protocol** لصفحة عامة واحدة: مسار الطلب، نوع المورد، حالة HTTP، ونوع المحتوى. تُحذف Query Strings ولا تُحفظ cookies أو Authorization أو Bodies أو response headers.
- **دقة V3:** مقارنة استجابة مسارات الدخول والإدارة بصفحة عشوائية غير موجودة (soft-404) لتقليل الادعاءات الخاطئة في تطبيقات SPA.
- **درجات الثقة:** مرصود من Network أو استجابة مميزة، موثق في HTML/OpenAPI، مستنتج من JavaScript، أو غير مؤكد عند تطابقه مع صفحة fallback. الحالة HTTP 200 وحدها ليست دليلًا على وجود صفحة إدارة فعلية.
- **OpenAPI العامة:** فحص محدود لمساري `/openapi.json` و`/swagger.json`، وعرض أسماء Endpoints وطرق GET/POST/PUT/PATCH/DELETE الموثقة دون إرسال طلبات لهذه العمليات أو حفظ نصوص الطلب/الاستجابة.
- **بصمات التقنيات وشهادة TLS:** تقرير CMS/PHP ومكتبات JavaScript والخادم والإصدارات فقط حين تظهر أدلة في HTML/Headers؛ لا تخمين لإصدار PHP أو قاعدة البيانات. كذلك تاريخ صلاحية الشهادة، جهة إصدارها، وبروتوكول TLS المتفاوض عليه إن توفر.
- يتصل Chromium بنطاق الموقع نفسه فقط مع تثبيت عنوان IPv4 عام موثوق من DNS وحظر الطلبات الخارجة عن النطاق، وPOST وWebSocket وservice workers. التشغيل اختياري عبر `ALEZZ_SECURITY_BROWSER=1` (افتراضي إن كانت مكتبة Playwright وChromium مثبتين).
- لا يعني ظهور مسار إدارة أنه غير محمي، كما يمكن أن تعيد تطبيقات SPA حالة 200 لأي مسار وهمي. راجع النتائج في خادمك.
- حفظ سجل الفحص والتقارير في Supabase باستخدام **service-role على الخادم فقط**، مع طبقة SQLite محلية لسرعة العمليات. جداول الخدمة تستخدم RLS بلا وصول مباشر من anon/authenticated.
- بدء فحص يدوي أو اختيار يومي/أسبوعي؛ على Render Free الجداول الزمنية **غير مضمونة** لأن الخادم قد يتوقف أثناء الخمول.

## بروكسيات مجانية من GitHub — بدون اشتراك

أُضيف دعم جمع واختبار بروكسيات HTTP العامة من مصدرين علنيين متجددين:
- [monosans/proxy-list](https://github.com/monosans/proxy-list) — `proxies/http.txt`.
- [proxifly/free-proxy-list](https://github.com/proxifly/free-proxy-list) — `proxies/protocols/http/data.txt`.

**تعمل ميزة البحث عن البروكسيات المجانية دون بيانات اشتراك**، لكنها لا تفترض صحة أي IP من GitHub: تجلب قائمة محدودة من مسار ثابت عبر HTTPS محمي بفحص العنوان العام، تقبل `http://ip:port` و`ip:port` فقط دون بيانات دخول أو مضيفين داخليين، وتختبر حتى 6 مرشحين بحركة GET عامة عبر CONNECT إلى `example.com` مع تدقيق شهادة TLS، وتحتفظ بثلاثة بروكسيات نجحت فعليًا كحد أقصى. النتائج مؤقتة لمدة 30 دقيقة ولا تُكتب عناوين البروكسيات المجانية إلى قاعدة البيانات أو GitHub.

- صفحة المسؤول تتضمن زر **فحص البروكسيات المجانية من GitHub** لمعرفة عدد المصادر والمرشحين والمجربين والناجحين. الطلب محمي بجلسة مسؤول وCSRF وتبريد 3 دقائق لتجنّب الضغط.
- `ALEZZ_SECURITY_FREE_PROXY_ENABLED=1` **مفعّل افتراضيًا**؛ عند غياب قائمة السماح لا يُعتمد إلا نطاق تطبيق العز نفسه `app-apk-oquy.onrender.com`. لفحص موقع آخر عبر البروكسي يلزم وضع النطاق الذي تملك حق اختباره صراحةً في `ALEZZ_SECURITY_PROXY_ALLOWED_HOSTS` على Render. لا توجد قائمة مفتوحة لجميع النطاقات.
- البوابة تستخدم البروكسيات المجانية **بعد نجاح اختبار HTTPS فقط**. إذا لم ينجح أي بروكسي، يعود الفحص المباشر المعتاد دون إعلان أن بروكسيًا نجح؛ يمكن تغيير السلوك إلى منع الاتصال المباشر عبر `ALEZZ_SECURITY_FREE_PROXY_REQUIRE=1`.
- البروكسيات التي توفرها أنت يدويًا في `ALEZZ_SECURITY_PROXY_URLS` لها الأولوية على المجتمع. وعند إيقاف `ALEZZ_SECURITY_PROXY_ENABLED=0` تتوقف الاتصالات عبر كل أنواع البروكسيات.
- بروكسيات الجمهور **غير موثوقة**؛ قد تراقب وجهات الاتصال، أو تكون بطيئة جدًا، أو تختفي بعد دقائق. لا تُرسل عبرها تسجيلات الدخول أو الكوكيز أو بيانات العملاء أو مفاتيح API. كل ما ينفّذه هذا المسار GET عام بدون حسابات، وTLS الأصلي يتم التحقق منه. لا يستخدم Chromium هذا المسار حاليًا.
- لا يُستبدل البروكسي عند كود `403` أو `429` أو تحدّي Cloudflare، ولا يُحاول تجاوز صفحة التحدي أو الحماية. الاختبار اليومي للمصادر **غير مضمون** على Render Free أثناء نوم الخدمة.

## البروكسيات الاحتياطية (محددة للمواقع المصرح بها)

إعدادات Render (Environment → Add Environment Variables / Secret):

```text
ALEZZ_SECURITY_PROXY_ENABLED=1
ALEZZ_SECURITY_PROXY_ALLOWED_HOSTS=example.com,www.example.com
ALEZZ_SECURITY_PROXY_URLS=http://USER:PASSWORD@proxy1.example.net:3128,http://USER:PASSWORD@proxy2.example.net:3128
```

- القائمة مجرد **مثال** وليست بروكسيات متاحة. لا توجد بروكسيات مُضافة افتراضيًا؛ يلزم شراء/توفير عناوين فعلية بنفسك. لا تحفظ بيانات البروكسي في GitHub.
- يدعم HTTP CONNECT proxy مع كلمة مرور اختيارية، حتى 6 بروكسيات مهيأة، ويستخدم بروكسيًا ثابتًا يحدده اسم النطاق؛ عند **خطأ اتصال شبكة فقط** يجرب بديلًا واحدًا كحد أقصى. لا يتم تدوير IP دوريًا ولا على `403` أو `429` أو تحدي Cloudflare. بقية الفحوصات تستمر بطلبات GET محدودة.
- لا يُستخدم البروكسي لأي نطاق إلا عند وجوده حرفيًا في `ALEZZ_SECURITY_PROXY_ALLOWED_HOSTS`؛ هذه القائمة **موافقة تشغيل صريحة من مسؤول الخدمة** وليست بديلًا عن تصريح مالك الهدف. دون قائمة سماح أو عناوين بروكسيات يستمر الفحص المباشر المعتاد.
- قبل الاتصال بالبروكسي يتم رفض عناوين DNS الخاصة أو المختلطة، وقبل طلب HTTP CONNECT يُربط الاتصال بعنوان **IP عام مُتحقق منه للموقع الهدف**، مع فحص شهادة TLS باسم النطاق الأصلي. يتطلب ذلك بروكسي يسمح بعملية CONNECT إلى IP عام على المنفذ 443؛ بعض خدمات البروكسي لا تدعم ذلك.
- **تنبيه خصوصية:** بيانات مصادقة بروكسي `http://` تُنقل إلى مشغل البروكسي في مرحلة CONNECT، ولا تعادل اتصال HTTPS مشفرًا بمشغل البروكسي. استخدم بروكسيًا موثوقًا ومُدارًا من طرفك أو شبكة موثوقة، وتجنب خدمات البروكسي العشوائية. حركة HTTPS للموقع نفسه تظل مشفرة ومتحققًا من شهادتها.
- كلمات مرور البروكسي لا تظهر في التقارير أو API أو واجهة الاستوديو. `/api/security/proxies` مخصص لمسؤول العز ويعرض العدد وحالة التهيئة فقط. معلومات نتيجة الفحص تعرض نوع الاتصال وعدد تعذرات الشبكة دون نشر رابط البروكسي.
- يستخدم فحص Chromium/DevTools وتحليل شهادة TLS الاتصال المباشر حاليًا؛ **لا** يتم تمريرهما عبر هذه البروكسيات. لا نضمن التفافًا على WAF أو أي حظر، ولا يُعاد طلب التحديات الداخلية.
- إذا فشلت جميع قنوات البروكسي المعتمدة، يعرض التقرير **فحصًا غير مكتمل** بدل التبديل سرًا إلى عنوان مباشر أو إعلان الموقع آمنًا.
- غيّر كلمة المرور من لوحة مزود البروكسي وأعد نشر Render عند تسربها؛ لا ترسلها في المحادثة.

## Cloudflare وغياب معامل ray

- المسارات التي تبدأ بـ `/cdn-cgi/challenge-platform/` تخص Cloudflare وليست صفحات إدارة أو API للموقع. لا يفتح مسار `orchestrate/chl_page/v1` منفصلًا عادة؛ يحتاج إلى معامل `ray` وسياق التحدي الأصلي.
- عند إرجاع `cf-mitigated: challenge` أو صفحة تحدي مع علامات موثوقة، يتوقف الفحص العميق ويعرض حالة **فحص غير مكتمل بسبب Cloudflare** دون مؤشر أمان رقمي؛ لا يحاول إعادة تشغيل التحدي أو تجاوزه.
- استجابة HTTP 401 أو 403 أو 429 العامة تُسجل كتقييد وصول، لا كثغرة في موقع العميل. لا تعني قيمة HTTP 403 وحدها أن سبب الرفض Cloudflare.
- لا تُدرج طلبات Cloudflare الداخلية في قوائم مسارات الدخول أو API أو سجل Chromium؛ وقد أُزيلت معاملات الاستعلام من Network لأسباب خصوصية. لذلك لا يُتوقع أن تعمل نسخة مسار الشبكة المجرّد عند فتحها مباشرة.
- إذا كنت تدير الموقع، راجع **Cloudflare Security Events/WAF** لمعرفة سبب التحدي، واستخدم بيئة اختبار مصرح بها أو تقارير أدواتك المحلية عند الحاجة. لا نُعطّل WAF أو نتجاوز حماية الموقع.

## الفحص السريع دون إثبات ملف

1. افتح مركز الأمان من حساب مسؤول العز TV.
2. أدخل رابط نطاق HTTPS عام في خانة الموقع.
3. يبدأ الفحص الآلي للسطح العام مباشرة، وتظهر حالة الفحص في قائمة المواقع.
4. افتح التقرير الأخير لمراجعة المؤشرات وتوصيات الإصلاح أو تصدير JSON.

لا حاجة لرفع ملف إثبات ملكية، لكن لا يزال الفحص محصورًا بجلسة مسؤول مع حماية CSRF وحدود لعدد المواقع ومعدل طلبات GET وفاصل بين الفحوصات. لا يُجري محاولات استغلال أو تسجيل دخول أو ضغط أو رفع ملفات. النطاقات الداخلية وlocalhost وعناوين IP محجوبة لحماية الخادم من SSRF. استخدم النظام فقط على مواقعك أو التي لديك تصريح بفحصها.

## الوحدات المتقدمة

الأدوات التالية **ليست مثبتة ولا تعمل تلقائيًا** داخل خدمة Render: OWASP ZAP، WPScan، Nuclei، Semgrep، Trivy، Nikto، testssl.sh، Wazuh.

تتوفر واجهة استيراد تقرير JSON من كل أداة بعد تشغيلها على بيئة اختبار مصرح بها أو على الشيفرة المملوكة. لا تُشغَّل محاولات استغلال أو Brute Force أو DoS أو أي تعديل لحالة الموقع من Render.

أنواع تحتاج تحققًا يدويًا أو مراجعة الشيفرة: SQLi، RCE، XSS، SSRF، IDOR/BOLA، مصادقة وتفويض، رفع الملفات، خطأ منطق الأعمال، سباق الطلبات، XML/LDAP/NoSQL، إدخال القوالب، تخزين الملفات، اتصالات الخدمات، وإصدارات CVE/SBOM. لا يجوز تفسير قائمة الفحوصات اليدوية على أنها نتائج اكتشاف.

## جلسة المسؤول

عند توفر `ALEZZ_SUPABASE_SERVICE_ROLE_KEY` أو `ALEZZ_SUPABASE_SECRET_KEY` على الخادم، تُخزن بصمة SHA-256 فقط لجلسة المسؤول في جدول Supabase محمي `aseel_admin_web_sessions` لكي لا تضيع عند إعادة تشغيل Render. لا يتم إرسال الأسرار أو مفاتيح الخدمة إلى المتصفح.

مدة كوكي المسؤول 30 يومًا متجددة عند الاستخدام، بحد مطلق 180 يومًا، وإعادة تحقق من دور المسؤول بصفة دورية. يمكن تسجيل الخروج في أي وقت لإبطال جلسة المتصفح. إعادة المصادقة بعد المهلة القصوى إجراء أمني مقصود. إغلاق المتصفح وحده لا يسجل الخروج.

## ملاحظات التشغيل

- لن يصل Render إلى `localhost` أو IP خاص داخل شبكتك؛ تحتاج عامل فحص محلي داخل الشبكة، مع تصدير تقرير JSON إلى المركز.
- أعلى مستوى دقة يأتي من ربط مصادر الشيفرة وبيئات الاختبار وإضافة أدوات CI/DAST/SAST. لا يمكن فحص كل ثغرات تطبيق ما بمجرد رابط URL.
- تأكد من إعداد مفتاح الخدمة على Render، دون نشره في GitHub أو المتصفح.
- لكل موقع طلبات GET محدودة مع مهلة محددة واتصالات HTTPS فقط. تشغيل Chromium قد يفشل أو يتأخر على Render Free؛ سيبقى تقرير الفحص الأساسي متاحًا دون الاعتماد عليه.
- يحفظ الاستيراد بيانات النتائج المستخلصة لا الطلبات الخام أو أرقام الجلسات الحساسة.
