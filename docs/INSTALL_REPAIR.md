# أسيل TV 1.4.0 — إصلاح تثبيت Android 4.4.4

هذه النسخة هي APK منفصل باسم `sa.aseel.tv.kitkatfix`، ولا تحاول تثبيتها كتحديث للنسخة السابقة `sa.aseel.tv.full`.

## سبب رفض التثبيت السابق
في تشغيل CI القديم، الشهادة SHA-256 للإصدار 1.3.0:
`3ab5314982c68224c1c36739eac51000eb28ffd8d2db22ce6ebd3cfe3c262a3e`
وفي الإصدار 1.3.1:
`285d8a0f353f08c648db17a523117c0370b557cc4665b243baced51a3e610950`.

كلاهما استخدم معرّف `sa.aseel.tv.full`، ولذلك لا يمكن تثبيت الثاني فوق الأول على Android. **لا تحذف النسخة الأصلية أو بياناتها.**

## كيف تثبّت
1. حمّل `aseel-tv-kitkat-install-fix.apk` من إصدار GitHub الجديد.
2. انسخه للشاشة أو نزّله مباشرة إليها، وتأكد من اكتمال التنزيل.
3. من إعدادات الشاشة، اسمح بالتثبيت من مصادر غير معروفة لتطبيق مدير الملفات المستخدم.
4. افتح الملف، وثبّت «أسيل TV | إصلاح التثبيت». ينبغي أن تظهر كتطبيق إضافي وليس تحديثًا.
5. افتح الإعدادات داخل التطبيق → «فحص HTTPS والشهادات» ثم جرّب الأفلام.

## إن استمرت رسالة «التطبيق غير مثبت»
- تحقق من وجود مساحة تخزين داخلية كافية؛ يحتاج نظام التثبيت مساحة مؤقتة أكبر من حجم APK نفسه.
- تأكد أن الجهاز Android 4.4.4/API19 وARM 32-bit، وأن ملف APK غير تالف، وأن التثبيت من مصادر غير معروفة مُفعّل.
- لا تخلط بين هذه الحزمة و`sa.aseel.tv.full`. ابحث عن اسم التطبيق الجديد.
- تحقّق من تنزيل الملف الكامل، لا من صفحة HTML باسم .apk.
- سجل أخطاء PackageInstaller/Logcat باستخدام ADB (عند توفره) يحدد سبب الرفض الدقيق.

## التحقق
GitHub Actions يفحص إصدار DEX المتوافق مع KitKat، وبنية ZIP، محاذاة ZIP، ABI armeabi-v7a، توقيع V1، ومعرّف الحزمة الجديد.
اختبار التثبيت على جهاز Huidi الفعلي لا يمكن محاكاته بشكل قطعي في CI.

## التوقيع الدائم
بناء GitHub Debug الحالي يولّد شهادة جديدة على بعض عمليات البناء. لتحديث هذه الحزمة لاحقًا دون إزالتها، يجب إعداد مفتاح توقيع إنتاجي خاص محفوظ ضمن GitHub Actions Secrets ثم الاستمرار بنفس المفتاح لكل تحديث. لا تنشر مفتاح التوقيع في المستودع.
